# 백엔드로 발전시키는 마스터 순서

완료된 학습 앱을 버리고 새 프로젝트를 시작하는 것이 아니라, 안정성을 확인하며 한 단계씩 전환한다. 아래 항목은 **아직 구현되지 않은 다음 작업**이다.

## P0 · 현재 버전 안정화

- [ ] 네트워크 가능한 환경에서 npm install, 잠금 파일 생성·커밋, 전체 타입 검사와 두 빌드 확인
- [ ] 실제 Chrome/Edge에서 preview 파일과 배포 주소를 각각 열어 저장·재열기·백업 확인
- [ ] GitHub Actions CI 결과 확인, 실패 원인 수정
- [ ] 사용자와 취소/배송 시나리오를 하나씩 실습해 이해하기 어려운 문구 개선
- [ ] 실제 자료를 넣지 않고 가상 데이터로 유지

통과 조건: 핵심 업무·백업·오류 시나리오가 반복 가능하고 사용자가 데이터 흐름을 설명할 수 있다.

## P1 · 저장 인터페이스 비동기화

- Repository.load/save/replace의 Promise 인터페이스, 로딩·오류·취소 상태 정의
- 네트워크 지연에서 중복 클릭 방지, 요청 ID, 충돌 응답 처리
- 단일 로컬 어댑터를 유지하며 온라인 어댑터의 계약 테스트 추가
- 백업 스키마 버전과 마이그레이션 정책, 이전 버전 되돌리기 설계

통과 조건: 지연/실패/재시도에서 데이터 손실과 중복 변경이 없다. 단일 탭 원칙 해제 여부는 별도 결정한다.

## P2 · 로그인과 사용자별 자료 분리

Supabase 같은 관리형 백엔드를 후보로 검토할 수 있지만 먼저 요구사항을 정한다.

- 사용자, 조직(workspace), 소속, 서버가 검증하는 역할 설계
- orders/tickets/approvals/policies/events에 workspace_id와 참조 제약
- 로그인·로그아웃·세션 만료·계정 삭제 처리
- 모든 읽기/쓰기 경로에 조직별 접근 정책
- 사용자 A의 자료를 사용자 B가 조회·수정·직접 요청할 수 없는지 서버/API 테스트
- 관리자 권한은 화면 선택으로 바뀌지 않게 서버에서 부여

통과 조건: 미인증/다른 조직/상담원 권한의 금지 작업이 **서버**에서 차단된다.

## P3 · 승인 업무 서버 이전

- 요청·승인·실행을 인증된 서버 명령으로 구현
- DB 트랜잭션 안에서 최신 주문·정책 버전 확인, 조건부 업데이트
- 주문별 활성 승인에 대한 데이터베이스 제약/잠금
- 실행 요청 고유 키(idempotency key), 재시도 시 동일 결과 반환
- 실패와 차단 기록을 보존하는 감사 로그, 보존 기간·접근 권한
- 시각 기준 서버화와 시간대 정책

통과 조건: 동시에 두 관리자가 눌러도 한 번만 실행하며, 승인 뒤 출고한 주문이 취소되지 않는다.

## P4 · 읽기 전용 외부 연동부터

- 실제 이용 가능한 쇼핑몰 API 권한·요금·사용 제한·데이터 형식 확인
- 서버 비밀 키 보관, 연결 테스트, 페이지네이션·증분 갱신·오류 재시도
- 동일 주문/문의의 중복 수집 방지, 최신 갱신 시각 표시
- CSV 기능 유지: 연동 불가/중단 시 대체 경로
- 외부 입력은 텍스트 데이터로 취급. HTML/프롬프트 명령으로 실행하지 않음

통과 조건: 읽기 API 장애에도 기존 자료와 출처를 잃지 않고, 최신이 아닌 자료를 실시간으로 표시하지 않는다.

## P5 · AI 초안과 메시지 발송

- AI는 우선 초안만 제안. 주문의 확정 필드와 승인된 정책을 제한적으로 제공
- 모르는 정보는 모른다고 하고 근거·버전·비용·시간을 표시
- 주문/고객 개인정보 최소화, 보존·전송 조건 검토
- 프롬프트 인젝션·허위 정보·오배송 안내·민감 정보 노출 평가
- 고객 발송은 사람 확인 뒤 실행, 테스트 수신자와 실제 수신자 구분
- 공급자 메시지 ID, 실제 발송 성공/실패/재시도·중복 방지

통과 조건: 규칙 기반 초안과 실제 AI 출력이 구분되고, 공급자 성공 응답 없이 ‘발송 완료’라 표시하지 않는다.

## P6 · 쓰기 연동과 상용 운영

실제 취소·환불은 마지막이다. 테스트 계정/샌드박스로 검증하고 되돌릴 수 없는 동작은 별도 확인을 둔다. 개인정보·소비자 대응·운영 보안은 적용되는 현재 법과 전문가 검토가 필요한 영역이다. 사용자 환경에 맞는 실제 운영 정책을 확정해야 한다.

- 재시도·타임아웃·부분 실패·보상 처리·정산 결과 확인
- 모니터링·장애 알림·로그 접근·주기적 백업·복원 연습
- 고객지원 연락처·사용 조건·보관/삭제 정책·사고 대응
- 실사용 부하·접근성·모바일·브라우저·보안 검사

**한 단계의 완료 증거 없이 다음 단계가 완료된 것처럼 설명하지 않는다.**
